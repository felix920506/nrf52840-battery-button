# nRF52840 battery switch

A battery-powered Matter-over-Thread switch for the **Seeed Studio XIAO
nRF52840**. It supports up to six external momentary buttons or latching
rocker/toggle switches. Each input appears as its own Matter Generic Switch;
the battery appears as a Power Source.

## Quick start

No build tools are needed. Release firmware creates a unique pairing code on
first boot. You will need a supported nRF52840 board, a USB cable, a Matter
controller, and a Thread border router. Only Home Assistant has been tested;
this is an uncertified Matter test device, and some ecosystems may reject it.

1. Download the UF2 file for your board from the
   [latest release](https://github.com/felix920506/nrf52840-battery-button/releases/latest):

   | Board | Release file | Switch inputs |
   |---|---|---|
   | Seeed XIAO nRF52840, Sense, Plus | `battery-switch-xiao-nrf52840.uf2` | D0–D5 |
   | Adafruit Feather nRF52840 Express, Sense | `battery-switch-feather-nrf52840.uf2` | A0–A5 |
   | Pro Micro nRF52840, nice!nano, SuperMini | `battery-switch-promicro-nrf52840.uf2` | See [user guide](docs/user-guide.md#hardware-and-wiring) |

   Only the XIAO image has been tested on hardware; the others are
   build-tested. The Feather and Pro Micro bootloaders need SoftDevice S140 v6;
   the XIAO needs v7. The bootloader drive's `INFO_UF2.TXT` shows the version.

2. Disconnect the battery. Connect the board over USB and double-press reset
   to enter its UF2 bootloader. A USB drive appears. Copy the downloaded UF2
   file onto it; the board restarts when the copy completes.

> [!CAUTION]
> **On macOS, do not copy firmware with Finder.** Finder can enter a crash
> loop. Use Terminal instead, replacing the filename and drive as needed:
>
> ```sh
> cp -X battery-switch-xiao-nrf52840.uf2 /Volumes/XIAO-BOOT/
> ```
>
> `ls /Volumes` shows the drive name. A final `Input/output error` is normal
> if the board has already restarted after receiving the file.

3. Open the board's USB serial port at 115200 baud:
   - macOS: `screen /dev/cu.usbmodem* 115200` (quit with Ctrl-A, then K)
   - Linux: `screen /dev/ttyACM0 115200`
   - Windows: PuTTY or Arduino Serial Monitor, using the board's COM port

   The device prints a QR code and manual pairing code. Close and reopen the
   port to print them again.

4. In your Matter controller, scan the QR code or enter the pairing code. The
   controller setup needs access to a Thread border router. Pairing can be done
   while the board is powered over USB.

5. Disconnect USB, then connect the battery. **Battery positive goes to 3V3,
   not BAT or 5V; never connect USB and a battery at the same time.** See the
   [hardware and wiring guide](docs/user-guide.md#hardware-and-wiring) for
   supported batteries and the CR2032 capacitor recommendation.

The pairing code stays the same across firmware updates and factory resets.
Keep it private: anyone in Bluetooth range who knows it can commission an
unpaired device, and physical USB access exposes the code. See the
[user guide](docs/user-guide.md) for updates, switch configuration, reset, and
troubleshooting.

## About the project

Built on nRF Connect SDK v3.4.1 and Zephyr. The application uses one event loop
in the main thread; interrupts only queue events. The Matter stack requires
Zephyr.
